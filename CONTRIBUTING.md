# Contributing

- Build: `make`. Test: `make test` (golden tests under `tests/golden/`, runner `tests/zevtest.c`, written in C: `build/zevtest golden|examples|zevfmt|zevpm|install`).
- A test is a directory with `input.zev` and one of `expected_output.txt` (run) or `expected_error.txt` (compile error).
  Extra `.zev`, `.c` and `.cpp` files in the directory are passed to the compiler; `args.txt` adds options
  (`{dir}` is the test directory, `{tmp}` a scratch directory).
- The standard library is Zevic code under `packages/Zevic/` (the `Zevic` package, sources in `src/`). `packages/Zevic/src/Convert.zev` is generated by `tools/gen_convert.py`.
- Keep commits small: one change, one commit, tests in their own commit when that reads better.
- The language is described in `docs/spec/zevic-spec.md`. If the compiler and the spec disagree, fix one of them in the same change.
- Needs clang 15 or newer to build the generated LLVM IR (`apt install clang`, `winget install LLVM.LLVM`, `brew install llvm`).

## Releases and release notes

CI builds the archives and publishes the GitHub release. Its notes come from `tools/release_notes.py`: the `CHANGELOG.md` section of `VERSION` (builds of `main` use `Unreleased`), then the commits since the previous `v*` tag. So write the changelog entry in the same commit as the change, and move `Unreleased` under the new version heading when you bump `VERSION` and the `version` in `packages/Zevic/zevic.toml` (the two must stay equal).
